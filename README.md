# NULL PLAYING

2026-09-10 최신 코드·릴리스·서버·QA 상태: [인수인계](docs/SESSION_HANDOFF.md).
현재 빌드 기준은 저장소 루트이며, 이전 사전 통합 폴더는 v24 보관본입니다.

플레이하지 않아도, 모험은 진행 중. 화면을 보고 있지 않은 동안의 실제 경과 시간을 전투·성장·모험담으로 이어 주는 자동 관찰형 RPG입니다.

공식 영문 브랜드는 `NULL PLAYING`, 한국어 발음 표기는 `널 플레이잉`입니다. Android 패키지 ID와 Kotlin 네임스페이스는 현재 브랜드에 맞춘 `com.nullplaying`을 사용합니다. 이전 `com.alarmquest` 설치본과는 Android에서 별도 앱으로 취급됩니다.

## 현재 규칙

- 캐릭터 생성 능력치는 Progress Quest 원본과 동일한 3d6 굴림입니다.
- 레벨업하면 최대 HP는 CON, 최대 MP는 `INT 50% + WIS 50%`를 기준으로 자원 성장합니다. 추가로 직업별 주·보조 능력치 중 하나와 HP·MP를 제외한 6개 기본 능력치 중 하나가 각각 1 증가합니다.
- 직업별 프롤로그 6편 뒤에 작가가 쓴 본편 24장이 이어지며, 각 장은 5막으로 자동 진행합니다.
- 본편 완결 뒤에는 `국경 수호록` 18편을 거쳐 깊이와 관문이 계속 증가하는 미궁으로 진입합니다.
- 장 시작 시 세부 적 변주를 서사 난수로 한 번 확정해 저장하며, 전투·전리품 난수와 섞어서 관리합니다.
- 5막을 완결하면 레벨업과 같은 직업 중심 능력치 성장을 한 번 적용하고 다음 장으로 즉시 넘어갑니다.
- 스킬은 5레벨마다 하나씩 자동 습득하며 최대 20개입니다.
- 스킬은 직업 적성 기본 발동률 8~20%에 `INT 50% + WIS 50%` 보너스를 더합니다. 일반 발동률 상한은 메이지 35%, 나머지 직업 30%이며, 기본 공격 15회가 연속되면 다음 공격은 스킬로 확정합니다.
- 발동 뒤에는 신규 스킬일수록 높은 선택 가중치를 받고 200회 사용까지 점진적으로 보통 가중치로 낮아집니다. 스킬이 둘 이상이면 직전에 발동한 스킬은 다음 선택에서 제외합니다.
- 장비는 더 강한 아이템을 발견하면 자동 교체합니다.
- 전투력은 직업별 주능력치 70% + 보조 능력치 30%를 레벨 기준으로 환산한 `능력치 전투력`과 6부위 평균 `장비 전투력`을 기준 50:50으로 합산합니다. 기본·스킬 공격의 능력치 기준도 동일한 70:30을 사용합니다.
- 가방 한도는 기본 15칸에 레벨 비례 보너스와 제한된 `STR / 2` 보너스를 더하며, 전리품 하나가 한 칸을 차지합니다.
- 몬스터 에너지는 현재 공격력과 목표 타격 수로 계산하며, 기본 공격 또는 보유 스킬이 발동할 때 실제 피해만큼 감소합니다.
- 몬스터와 아이템 이름은 조합 생성하고 최근 이름을 제외해 반복을 줄입니다.
- 지역 선택, 도감, 강화, 프리셋, 수동 정산은 없습니다.
- 앱 재실행 시 마지막 저장 시각부터 현재까지를 즉시 계산합니다. 플랫폼 `JobScheduler`는 진행 알림 시점에만 사용합니다.
- 오프라인 모험은 Remote Config 기본 시간(현재 8시간)에 CON·레벨 보너스를 최대 25% 더해 저장하며, 전경 플레이 20분으로 완전히 충전합니다. 이미 충전한 시간은 원격 상한이 낮아져도 보존합니다.
- DEX는 몬스터 탐색 시간을 기본 5초에서 최소 3.5초로 줄이며, CHA는 전리품 판매액을 최대 15% 높입니다. 성직자의 주·보조 능력치는 WIS/CHA입니다.

## 저장 구조

Room 16의 `simple_game_state`에 최대 3개 캐릭터 슬롯을 저장하고 `simple_account_progress`에 계정 공용 진행을 저장합니다. 저장 직전의 정상 JSON은 앱 내부의 별도 원자적 백업 파일로 보존하며, 현재본을 해석할 수 없으면 백업본으로 자동 복구합니다. JSON 상태 스키마는 엔진과 모델이 하나의 버전 상수(현재 46)를 공유합니다. Room 12→13→14→15→16은 비파괴 자동 마이그레이션을 선언합니다.

Android 시스템 백업과 기기 이전은 현재 비활성화되어 있습니다. 따라서 앱 제거, 앱 데이터 삭제 또는 기기 분실 시 로컬 진행과 설치별 익명 계정을 복구할 수 없습니다.

## 화면

상단 자동 전투 영역은 모든 메뉴에서 유지됩니다. 하단 메뉴는 메인, 모험가, 결투장, 아이템, 퀘스트의 5개이며 스크롤 없이 고정됩니다. 퀘스트 탭은 현재 모험담의 5막 타임라인과 완결된 `지난 모험담`을 표시합니다.

상세 콘텐츠·데이터·UI 원칙은 [`QUEST_TALE_SYSTEM_PLAN.md`](QUEST_TALE_SYSTEM_PLAN.md)에 정리했습니다.

## 검증 및 릴리스

새로 체크아웃한 환경에서는 Firebase의 게임 Android 앱(`com.nullplaying`)에서 내려받은
`google-services.json`을 `app/`에 두어야 합니다. 실제 Firebase 클라이언트 설정은 로컬에만
보관하며, 필요한 파일 구조는 [`app/google-services.example.json`](app/google-services.example.json),
설정·운영 방법은 [`docs/FIREBASE_REMOTE_CONFIG.md`](docs/FIREBASE_REMOTE_CONFIG.md)를 참고하세요.
서명키, 비밀번호, `local.properties`, 빌드 산출물 및 비공개 광고 수익 자료는 Git에 포함하지 않습니다.

일반 회귀 검증:

```bash
./gradlew :app:testDebugUnitTest :app:testReleaseUnitTest :app:lintRelease :app:assembleRelease :app:bundleRelease
```

서명된 Play 제출용 AAB는 전용 업로드 키를 재사용해 다음 명령으로 만듭니다.

```bash
./tools/build_android_release.zsh
```

스크립트는 키체인 또는 Git에서 제외된 로컬 비밀번호 파일을 사용하고, 업로드 인증서 SHA-256 지문
`45:EE:A2:23:C8:3F:2A:C6:F7:98:F2:AC:54:1B:FE:A2:70:E0:DD:74:70:AE:95:D9:FC:2C:4E:AD:4A:73:FD:D2`가 일치하지 않으면 중단합니다. 키스토어와 비밀번호는 저장소에 커밋하지 않습니다.

출력은 `app/build/outputs/bundle/release/app-release.aab`입니다. 로컬 서명 성공은 Google Play의 버전 코드 및 업로드 키 수용을 증명하지 않으므로 내부 테스트 트랙 업로드로 별도 확인해야 합니다.
