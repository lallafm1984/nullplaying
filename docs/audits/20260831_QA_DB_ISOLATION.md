# 운영 DB 테스트 데이터 정리 및 QA 격리

2026-08-31 Remote Config 검증 중 운영 Supabase에 QA 계정이 생성된 문제를 수정했습니다.

- 대상: 에뮬레이터 로컬 인증 ID로 확인한 1개, 같은 검증 시간대의 `robolectric` 테스트 계정 29개.
- 기준: UTC 10:26–10:34 생성 시각, 기기 모델·제조사, 익명 인증 여부를 읽기 전용 조회로 확인하고 30개 UUID를 고정했습니다.
- 관리자 계정과 랭킹 보유 계정은 삭제 후보에서 제외했습니다. 실제 후보에는 랭킹·게임 세션 로그·일별 집계가 없었습니다.
- 단일 트랜잭션에서 테스트 가입 이벤트 30개, 가입자 통계 행 30개, 인증 사용자 30개와 관련 프로필·인증 세션·갱신 토큰을 정리했습니다.
- 삭제 이벤트가 새로 생성되지 않도록 대상 가입자 통계 행을 Auth 사용자보다 먼저 삭제했습니다.
- 트랜잭션 안에서 다른 사용자 ID, 관리자 데이터, 관리자 기기, 시스템 랭킹의 보존을 검증했습니다.
- 독립 재조회에서 대상 사용자·프로필·랭킹·세션 로그·집계·가입자 행·가입 이벤트·인증 세션·갱신 토큰은 모두 0건이었습니다.

재발 방지:

- `debug`, `migrationTest`의 Supabase URL과 키는 빈 값입니다. 릴리스 설정은 유지합니다.
- `SupabaseGameService`는 디버그 빌드에서 인증·조회·쓰기·업로드 대기열 생성을 중단하며 HTTP 요청 입구에서도 차단합니다.
- Firebase Remote Config는 독립적으로 계속 동작합니다.
- QA 계정의 기기 내 인증 정보와 대기열을 제거하고 수정 APK를 데이터 유지 설치했습니다.
- 차단 회귀 테스트 포함 27개 테스트, debug 빌드 통과. QA 앱 재실행 후 인증/업로드 대기열 미생성과 운영 DB 신규 QA 사용자 0건을 확인했습니다.

관리자 1개, 관리자 기기 1개, 시스템 랭킹 20개를 보존했습니다. 실제 사용자 신규 유입은 삭제 대상에 포함하지 않았습니다. Supabase 플랫폼 운영 로그와 이미 전달된 푸시 알림은 이 DB 정리 범위 밖입니다.

로컬 증거: `tmp/qa-db-cleanup/before.json`, `targets.json`, `delete-exact-targets.sql`, `after.json`, `after-qa-relaunch.json`, `build.log`.
