# 최종 능력치 보너스 검토 및 반영

## 기획 판정: 직업 개성 우선 방향으로 채택, 코드 검증 완료는 출시 승인과 별개

2026-09-01. 사용자는 전 직업 효율 평준화보다 특화를 우선하고, 검토를 통과한 안만 코드 반영하도록 요청했다. 기존 6% 성장 격차 기준을 통과했다고 주장하지 않는다. 새 임의 수치 기준으로 합격선을 바꾸지도 않는다.

- 종전 DEX3.5초 안 144경로에 더해, 미사용 seed 38~45의 전 직업 48경로를 120레벨까지 추가 재생했다. 5,760행의 수식·상한·단조성·직업별 비특화 상한 미도달 검증 통과.
- **기본 8시간·완충 12분이라는 이전 조건**의 새 표본에서 20~100레벨 최대 성장 격차 7.0065%, 20~120레벨은 9.5262%, 판매 수입 격차 10.2954%. 기존 표본 최대 성장 격차 7.7682%. 서로 다른 구간/표본을 섞어 최저 수치만 보고하지 않는다. 최종 요청은 기본 8시간·완충 20분이며 해당 결과는 아래 별도 기록한다.
- 마법사 8개 경로 모두 100레벨에서 35% 미달, 최초 도달 107~112레벨. 상한은 일반 발동 확률이며 15연속 일반 공격 뒤 확정 발동은 별도다.
- 접속 패턴에 따라 성장 우위 직업이 바뀌고, 판매/가방 등 특화가 분리된다. 8시간 이내에 항상 완충하는 경우 전사의 시간 특화 효용은 제한적이다.
- 120레벨까지 추가 확인했지만 그 이후 장기 경제, 실제 사용자 로그, 광고 이용 패턴, 이탈률 검증은 아니다. 캘린더 효율은 반복 접속 근사값이다.

## 적용할 식

`x=clamp((L-1)/99,0,1)`

- CON 시간: `Remote Config 기본 시간 × [1 + 0.25 × min(CON/150,1)^1.2 × (0.15+0.85×x^1.2)]`. 기존 시간 키/캐시를 그대로 사용한다. 최종 확정 기본 8시간이면 최대 10시간이며, 나중에 기본을 12시간으로 바꾸면 최대 15시간이다.
- 정신력: `(INT+WIS)/2`. 추가 발동률 `15×min(정신력/180,1)^1.2`%p. 기존 직업 적성 기본률 유지. 마법사 35%, 나머지 30% 상한.
- DEX 탐색: `5−1.5×min(DEX/150,0.12+0.88×x^1.4)`초, 최소 3.5초. 발견 연출 2초 별도.
- CHA 판매: `15×min(CHA/150,0.12+0.88×x^1.4)`%. 실제 금액은 정수 절삭.
- 성직자 WIS/CHA, 능력치/HP/MP 성장 및 STR 가방 산식은 변경하지 않는다.

## 구현에 필요한 보완

1. 사용자의 후속 요청을 우선하여 기존 `offline_adventure_capacity_minutes`를 기본 시간으로 삼고 최대 25% CON 가중치를 곱한다. 검토 중 시도한 별도 v2 키/고정 8시간 방식은 채택하지 않았다. 최종 사용자 승인값은 로그 ON / 기본 480분 / 완충 20분이며 앱 기본값도 일치시킨다.
2. 현재 잔여 시간은 상한이 낮아져도 삭제하지 않고 소진될 때까지 보존한다. 새 충전/광고는 새 직업별 상한까지만 지급한다. 상한 상승만으로 시간을 지급하지 않는다.
3. 밀리초 단위 동적 상한에 맞춘 충전 잔여 분수 버전을 저장한다. 기존 분수는 한 번만 변환하며, DB 구조 변경 없이 게임 JSON 필드로 호환한다.
4. 판매 Double 연산의 `100×1.15→114` 절삭 오차를 피하기 위해 10억분율로 양자화 후 정수 연산한다. 발동률은 1만분율, 시간은 밀리초로 양자화한다.
5. 탐색/발견 UI 경계는 저장된 실제 행동 지속시간을 사용한다. 기존 진행 중인 탐색의 시간도 끊지 않는다.
6. 순수 JVM에서만 테스트한다. 네트워크·DB 파일을 OS 수준에서 차단하며 Android/Room/Firebase/Supabase를 시작하지 않는다. 빌드와 배포/기기 실행을 구분한다.

## 로그와 랭킹

- 기존 세션 로그는 5분 미만 홈 이동을 폐기했고 백그라운드 즉시 송신도 없었다. 앱 전체 Activity가 숨겨질 때 `background`, 정상 종료 시 `exit`를 로컬 대기열에 먼저 저장하고 전송을 시도하도록 변경했다.
- 전체 화면 광고를 포함해 Activity 가시성을 추적한다. 앱 내부 화면 전환/회전/중복 stop-destroy를 별도 앱 종료로 오인하지 않는다.
- 기존 대기 로그 복원은 안정된 event_id를 사용한다. HTTP409는 해당 event_id의 PK 중복일 때만 성공으로 취급하며 다른 오류는 큐를 유지한다.
- `app_session_logs_enabled`: OFF에서는 새 로그 생성/송신 중단, 기존 대기열 보존; ON 이후 재전송. 시간 값 검증 실패와 독립적으로 스위치를 반영한다. QA 차단보다 우선하지 않으며 랭킹/인증/프로필에는 적용하지 않는다.
- 기존 대기열 100건 상한 유지. 전송 중인 요청의 소급 취소, 콜백 이전 강제 종료의 누락 방지, 즉시 서버 도착은 보장하지 않는다. [Android 생명주기 문서](https://developer.android.com/guide/components/activities/activity-lifecycle).
- 랭킹은 변경하지 않았다. 20레벨 이상 캐릭터 ID/슬롯/이름/직업/레벨/전투력을 대기열에 저장, 복귀 및 접속 중5분 주기로 송신 시도, 성공 후5분 간격 제한, 같은 데이터 생략. 홈/종료는 저장만 하고 다음 전송 시점까지 대기한다. 실패 시 유지하고 전송 중 갱신된 대기 데이터는 지우지 않는다.
