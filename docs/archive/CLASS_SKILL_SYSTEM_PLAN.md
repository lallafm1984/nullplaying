# NULL PLAYING 직업별 600 스킬 및 전투 연출 기획 v1

상태: 구현 전 확정안 후보  
범위: 전사·도적·순찰자·마법사·성직자·성기사, 직업당 100개 / 총 600개

## 1. 핵심 규칙

- 기존 규칙인 `5레벨마다 1개 습득`, `최대 20개 보유`, `스킬 발동률 45%`를 유지한다.
- 직업마다 20개의 습득 구간을 두고, 각 구간에 같은 위력의 후보 5개를 배치한다.
  - Lv.5 후보 5개 중 1개 무작위 습득
  - Lv.10 후보 5개 중 1개 무작위 습득
  - ...
  - Lv.100 후보 5개 중 1개 무작위 습득
- 따라서 한 캐릭터는 직업별 전체 100개 중 20개를 갖는다.
- 같은 습득 레벨의 후보 5개는 총 피해량이 같다. 랭킹과 성장 속도는 운에 따라 달라지지 않는다.
- 모든 스킬은 적에게 직접 피해를 주는 공격 기술이다. 버프·회복·지속 피해·상태 이상은 추가하지 않는다.
- 전투 승리는 기존처럼 시간과 공격 횟수로 계산한다. 피해 숫자와 다단히트는 전투 결과를 설명하는 연출이다.
- 오프라인 정산에서는 개별 타격 연출을 재생하지 않는다. 기존 시간 기반 일괄 계산을 그대로 사용한다.

## 2. 습득과 저장

- 신규 캐릭터는 생성 시 변경되지 않는 `skillCatalogSeed`를 한 번 만들고 저장한다.
- 레벨업 시 `hash(skillCatalogSeed, heroClass, tier) mod 5`로 해당 구간 후보를 결정한다.
  - 게임 RNG와 전투 연출 RNG를 모두 소비하지 않는다.
  - 같은 저장 데이터에서는 재시작·미접속 정산 여부와 관계없이 같은 스킬을 얻는다.
- 구간마다 한 번만 뽑기 때문에 중복 스킬은 발생하지 않는다.
- 현재 캐릭터의 기존 공용 스킬은 진행을 지우지 않고 직업별 스킬로 변환한다.
  - `skillCatalogSeed + 직업 + 습득 구간 + 기존 스킬 ID`의 고정 해시로 후보를 선택한다.
  - 게임 RNG와 전투 연출 RNG를 소비하지 않아 마이그레이션 전후 드롭·퀘스트·미접속 결과가 바뀌지 않는다.
- 저장 데이터는 스킬 이름이나 연출 전체가 아니라 안정적인 카탈로그 ID를 기준으로 한다.
  - 예: `warrior_t03_c04`, `mage_t08_c02`
  - 이름·속성처럼 추후 바뀔 수 있는 값은 ID에 넣지 않는다.
- 카탈로그 이름·설명·연출이 수정되어도 ID와 습득 레벨은 유지한다.
- 파티클 위치·좌우 방향·색조의 작은 변화는 `hash(actionSequence, catalogId)`로 만든 UI 전용 난수를 사용한다. Compose 재구성이나 앱 복귀로 모양이 바뀌지 않는다.

## 3. 피해량 규칙

| 습득 레벨 | 총 피해 배율 | 습득 레벨 | 총 피해 배율 |
|---:|---:|---:|---:|
| 5 | 120% | 55 | 150% |
| 10 | 123% | 60 | 153% |
| 15 | 126% | 65 | 156% |
| 20 | 129% | 70 | 159% |
| 25 | 132% | 75 | 162% |
| 30 | 135% | 80 | 165% |
| 35 | 138% | 85 | 168% |
| 40 | 141% | 90 | 171% |
| 45 | 144% | 95 | 174% |
| 50 | 147% | 100 | 177% |

- 같은 레벨의 1타·3타·5타 스킬은 표시되는 피해 합계가 동일하다.
- 배율은 개별 스킬 데이터에 중복 저장하지 않고 `120 + (tier - 1) × 3`으로 계산한다.
- 분할 비율:
  - 1타: `100`
  - 2타: `48 / 52`
  - 3타: `28 / 32 / 40`
  - 4타: `20 / 22 / 25 / 33`
  - 5타: `15 / 17 / 18 / 20 / 30`
- 총 피해를 기존 방식으로 한 번만 계산한 뒤 앞 타격은 내림으로 분할하고, 남은 피해를 마지막 타격에 더한다.
- `hitWeights`는 1~5개, 모두 양수, 합계 100이어야 하며 `sum(hitDamages) == totalDamage`를 항상 만족한다.
- 피해가 작은 초반에 일부 중간 타격이 0이 되어도 합계를 부풀리기 위한 최소 1 피해는 강제하지 않는다.
- 기본 공격은 지금처럼 기술명 없이 중앙 피해 숫자 1개만 표시한다.

## 4. 연출 시스템

한 스킬마다 별도 애니메이션 코드를 만들지 않고 다음 메타데이터를 조합한다.

`classLanguage + elementPalette + motion + timingProfile + path + impact + particle + backdrop + camera + finisher + intensityTier + labelAccent`

- 직업은 동작의 기하학을, 속성은 재질과 색을, 모션은 궤적을, 타이밍 프로필은 타격 리듬을 결정한다.
- 같은 직업 안에서 `motion + timingProfile + element + finisher`가 완전히 같은 조합은 허용하지 않는다.
- 카탈로그 ID 해시는 궤적 각도 ±8도, 색조 ±4도, 좌우 방향, 입자 위치만 바꾸며 타격 시점과 피해 분할은 바꾸지 않는다.

### 타격 시간표

한 번의 공격 이벤트는 기존 1,400ms를 유지한다.

| 타수 | 피해 표시 시점(ms) |
|---:|---|
| 1 | 420 |
| 2 | 240, 680 |
| 3 | 180, 430, 720 |
| 4 | 140, 320, 520, 760 |
| 5 | 110, 250, 400, 570, 780 |

- 스킬명은 첫 타격 직전에 한 번 나타나 마지막 피해가 사라질 때까지 고정한다.
- 각 피해 숫자는 동일한 중앙 기준점을 사용한다.
- 연속 타격은 매 타격마다 빠르게 확대·축소하고, 마지막 타격만 크기와 흔들림을 15% 강화한다.
- 몬스터 게이지는 UI에서만 한 공격분의 감소량을 `hitWeights`에 따라 나눠 각 타격 시점에 90~120ms 동안 계단식으로 깎는다.
- 마지막 타격에서 엔진이 저장한 목표 게이지 값으로 정확히 맞춘다. 몬스터가 쓰러지는 공격은 반드시 0%가 된다.
- 엔진은 다단히트도 공격 1회로 처리한다. `attacksCompleted +1`, `actionSequence +1`, 저장 에너지 감소 1회라는 기존 계약을 유지한다.
- 스킬 발동 판정도 공격 이벤트당 한 번만 45%이며, 타수별로 다시 판정하지 않는다.
- 실제 VFX는 1,100ms까지 끝내고 1,250ms에 모든 임시 상태를 강제 초기화한다. 마지막 150ms는 다음 공격을 위한 완전한 정지 구간이다.

### 타격 리듬 프로필

기본 시간표에 아래 리듬을 적용해 같은 타수의 스킬도 읽히는 느낌을 다르게 만든다. 마지막 타격은 항상 900ms 이전이다.

| ID | 리듬 | 사용감 |
|---|---|---|
| `RAPID` | 앞 타격을 80~160ms 간격으로 몰아치고 짧게 마무리 | 단검·연사·번개 |
| `EVEN` | 타격 간격을 거의 동일하게 유지 | 검무·연속 사격·광선 |
| `DELAYED_FINISH` | 중간 타격 뒤 180~260ms 정적 후 큰 마무리 | 처형·망치·심판 |
| `ACCELERATE` | 뒤로 갈수록 간격이 짧아짐 | 광전·폭풍·연쇄 마법 |
| `DECELERATE` | 첫 타격이 빠르고 뒤로 갈수록 무거워짐 | 대지·빙결·성추 |

### 중앙 피해 숫자와 스킬명

| 타수 | 중간 피해 숫자 | 마지막 피해 숫자 |
|---:|---:|---:|
| 1 | - | 46sp / 최대 420ms |
| 2 | 38sp / 최대 280ms | 43sp / 최대 340ms |
| 3 | 34sp / 최대 220ms | 42sp / 최대 320ms |
| 4 | 31sp / 최대 170ms | 40sp / 최대 290ms |
| 5 | 28sp / 최대 140ms | 40sp / 최대 280ms |

- 숫자는 모두 같은 중앙 좌표에 하나씩만 표시한다. 새 타격 전에 이전 숫자는 투명도 25% 이하가 되고 8~14dp 위로 흘러 사라진다.
- 기본 공격과 스킬의 피해 숫자 기준점은 완전히 같다. 스킬명 카드가 있을 때만 숫자와 카드 묶음 전체를 함께 위·아래로 보정한다.
- 스킬명 카드는 피해 숫자 위 중앙에 고정하고 확대·회전·좌우 이동시키지 않는다. 마지막 타격 뒤에도 최대 100ms 유지한 후 140ms 페이드아웃한다.
- 카드 높이 30~32dp, 최대 너비 236dp, 16sp SemiBold, 한 줄 말줄임을 사용한다. 긴 스킬명도 피해 숫자 중심축을 바꾸지 않는다.

### 접근성 안전선

- 전체 화면 순백색 점멸은 사용하지 않는다.
- 섬광은 최대 120ms, 불투명도 18% 이하로 제한한다.
- 입자는 동시에 최대 32개, 수명 150~650ms, 궤적 두께 1~5dp로 제한한다.
- 시스템 애니메이션 감소 설정에서는 흔들림을 0으로, 확대를 1배로 고정하고 이동 거리를 50% 이하로 줄인다. 색·형태·순차 피해 숫자는 유지한다.
- 색상만으로 속성을 구분하지 않고 궤적·입자 형태를 함께 사용한다.
- 밝고 어두운 패널 상태를 번갈아 반복하지 않으며 3Hz 이상의 점멸을 금지한다.
- 자동전투의 매 타격을 TalkBack live region으로 읽지 않는다. 전투 영역에 초점이 있을 때만 `스킬명, 총 피해, 5회 공격`처럼 공격 이벤트를 한 번 요약한다.

### 화면 레이어 순서

모든 스킬은 아래 8개 레이어를 필요한 만큼 조합한다. HUD와 몬스터 이름·등급은 항상 최상단에서 읽을 수 있어야 한다.

1. 기본 전투 배경
2. 속성 배경 tint와 가장자리 vignette
3. 몬스터 뒤쪽 환경 입자
4. 무기·화살·마법 궤적
5. 몬스터 앞쪽 충돌 입자와 충격파
6. 중앙 피해 숫자
7. 스킬명 카드
8. 몬스터 이름·등급·게이지

- 속성 tint·섬광·흔들림·확대·입자는 전투 이미지 영역에만 적용하고 상단 58dp의 몬스터 이름·등급·게이지 영역에는 적용하거나 통과시키지 않는다.
- `actionSequence`가 바뀌면 이전 스킬의 입자·tint·잔광을 즉시 취소하고 새 연출 상태를 시작한다.
- 전투 종료·귀환·메뉴 전환·화면 재구성·백그라운드 복귀 시 연출을 재생하지 않고 모든 emitter와 피해 숫자를 제거하며 backdrop alpha 0, label alpha 0, translation 0, scale 1로 되돌린다.

### 레벨에 따른 연출 강도

위력 배율뿐 아니라 연출 규모도 점진적으로 성장시킨다. 색상과 입자 수만 늘리고 화면을 덮는 불투명도는 제한한다.

| 단계 | 습득 레벨 | tint 최대 | 입자 권장 수 | 흔들림 최대 | 추가 확대 |
|---:|---:|---:|---:|---:|---:|
| I | 5~20 | 8% | 4~7 | 2dp | 0.6% |
| II | 25~40 | 10% | 7~11 | 3dp | 0.9% |
| III | 45~60 | 12% | 10~15 | 4dp | 1.2% |
| IV | 65~80 | 14% | 14~21 | 4dp | 1.6% |
| V | 85~100 | 14% | 18~28 | 4dp | 2.0% |

- 같은 행의 후보 5개는 연출 강도 단계도 동일하다.
- 입자는 저사양 기기에서 단계별 하한 수로 자동 축소한다.
- 마지막 타격은 표의 최대값을 사용할 수 있지만 앞 타격은 최대값의 40~70%만 사용한다.

### 직업별 시각 언어

- 전사: 굵은 궤적, 낮고 무거운 충격음형 움직임, X/Y축 반동. 마지막 타격의 먼지와 균열을 강조한다.
- 도적: 가는 궤적, 짧은 잔영, 빠른 교차 방향. 화면 전체보다 중앙 주변의 속도감을 강조한다.
- 순찰자: 화면 가장자리에서 중앙으로 들어오는 투사체와 낙하 궤적. 배경 흔들림은 가장 약하게 유지한다.
- 마법사: 속성 tint와 환경 변화가 가장 크다. 얼음·불·번개·비전·우주의 형태 차이를 확실하게 만든다.
- 성직자: 위에서 아래로 내려오는 광선과 원형 성문양. 피해 숫자보다 빛의 시작과 확산이 먼저 보이게 한다.
- 성기사: 좌우 대칭 궤적, 방패형 원, 십자 충격. 전사보다 흔들림은 작고 금빛 잔광은 길게 유지한다.

### 대표 스킬 상세 타임라인

#### 전사 `삼중 베기`

- 0~100ms: 스킬명 진입, 배경 0.4% 확대
- 180ms: 28% 피해, 좌→우 칼날, 게이지 1단 감소
- 430ms: 32% 피해, 우→좌 칼날, 게이지 2단 감소
- 720ms: 40% 피해, 수직 마무리, 4dp Y축 충격, 게이지 최종 감소
- 720~1,100ms: 마지막 숫자와 금속 불꽃이 함께 감쇠

#### 마법사 `얼음 창`

- 0~180ms: 전투 이미지가 청색으로 변하고 가장자리에 옅은 서리 생성
- 180~360ms: 화면 왼쪽에서 청백색 창이 중앙으로 이동
- 420ms: 단일 피해, 얼음 금과 육각 파편, 게이지 감소
- 420~760ms: 피해 숫자가 흰색에서 하늘색으로 변함
- 760~1,100ms: 서리와 tint가 천천히 사라지고 기본 배경으로 복귀

#### 마법사 `눈보라`

- 0~120ms: 청색 tint와 사선 눈 입자 시작
- 140/320/520ms: 작은 냉기 피해 3회, 각 시점에 게이지 계단 감소
- 760ms: 가장 큰 빙결 폭발과 마지막 피해
- 760~1,100ms: 가장자리 결빙이 녹듯이 사라짐

#### 도적 `무영천살`

- 0~110ms: 배경을 8% 어둡게 하고 스킬명만 유지
- 110/250/400/570ms: 방향이 교차하는 잔영 타격 4회
- 780ms: 160ms 정적 뒤 굵은 보라 선과 마지막 피해
- 마지막 타격에만 2% 확대와 4dp X축 반동 적용

#### 순찰자 `무한성우`

- 0~110ms: 상단에 희미한 화살 그림자 생성
- 110/250/400/570ms: 서로 다른 X좌표에서 화살 4개 낙하
- 780ms: 굵은 중심 화살과 바람 원형파
- 카메라 흔들림은 2dp 이하, 투사체 밀도로 속도감을 표현

#### 성직자 `천국문 폭격`

- 0~180ms: 중앙 상단에 금백색 원형 문양 생성
- 250/430/610/780ms: 네 갈래 광선이 순차 강하
- 마지막 타격 뒤 작은 깃털 입자가 아래로 흩어짐
- HUD는 tint 대상에서 제외해 몬스터 이름과 게이지 대비 유지

#### 성기사 `절대성벽`

- 0~220ms: 중앙에 반투명 금빛 방패 원 생성

## 6. 구현 데이터 구조 제안

```kotlin
data class SkillDefinition(
    val catalogId: String,
    val heroClass: HeroClass,
    val unlockLevel: Int,
    val name: String,
    val descriptionTemplate: String,
    val hitWeights: List<Int>,
    val element: SkillElement,
    val motion: SkillMotion,
    val timingProfile: SkillTimingProfile,
    val path: SkillPath,
    val backdrop: SkillBackdrop,
    val impact: SkillImpact,
    val particle: SkillParticle,
    val camera: SkillCamera,
    val finisher: SkillFinisher,
    val labelAccent: SkillLabelAccent,
)

val SkillDefinition.damagePercent: Int
    get() = 120 + ((unlockLevel / 5) - 1) * 3

data class LearnedSkill(
    val catalogId: String,
    val acquiredAtLevel: Int,
)
```

설명은 공격 기술임을 즉시 알 수 있도록 카탈로그 메타데이터에서 만든다.

- 1타: `"{name}으로 적을 강하게 공격한다."`
- 2~5타: `"{name}으로 적을 {hitCount}회 연속 공격한다."`
- 비공격으로 오해할 수 있는 명사형 이름은 사용하지 않고 `관통·절단·폭발·강습·격돌·붕괴`처럼 공격 결과가 읽히는 단어를 포함한다.

영구 저장은 `catalogId + acquiredAtLevel`만 진실의 원천으로 삼는다. 전투 중 화면에 필요한 일시 값은 최소화한다.

```kotlin
var lastSkillCatalogId: String = ""
var lastTotalDamage: Long = 0L
var actionSequence: Long = 0L
```

- UI는 `lastSkillCatalogId`로 카탈로그를 조회해 연출한다.
- 온라인 UI에서만 `lastTotalDamage`와 카탈로그의 `hitWeights`로 타격별 피해를 파생한다. `lastHitDamages`는 저장하지 않는다.
- 현재 저장 구조가 스키마 11이면 12로 올리고, 이행 릴리스에서는 기존 `LearnedSkill.id/name/description`을 deprecated 필드로 읽을 수 있게 유지한 뒤 변환한다.
- `skillCatalogSeed`가 없는 저장은 기존 RNG 상태와 영웅·직업을 순수 해시해 한 번 만들되 두 RNG 스트림 자체는 소비하지 않는다.
- 정의를 찾지 못한 `catalogId`는 삭제하지 않고 안전한 1타 물리 연출로 표시한다.
- 오프라인 정산은 기존처럼 공격 이벤트 수와 시간을 계산한다.
- 스킬 메타데이터는 저장 파일에 복제하지 않아 카탈로그 수정과 저장 용량 증가를 막는다.

### 시스템 불변 계약

- `damagePercent`, hitCount, element, 모션, 속성 tint는 전투 종료 시각·처치 수·드롭·퀘스트·장비·전투력·랭킹 계산에 넣지 않는다.
- 1~5타 모두 공격 이벤트 1회이며 저장 에너지는 기존 공격 1회분만 감소한다.
- 발동 여부·보유 스킬 선택·표시 총 피해 편차만 기존 presentation RNG가 담당한다.
- 후보 습득과 장식 파티클은 gameplay RNG와 presentation RNG를 소비하지 않는다.
- 오프라인 정산은 presentation RNG를 소비하지 않고 연출 필드를 비운다.
- 새 공격이 시작되면 이전 연출 coroutine과 emitter를 취소하고 중립값으로 snap한 뒤 단일 1,400ms 시계에서 새 연출을 파생한다.
- 각 타격에서 피해 숫자 교체·게이지 단계 이동·충격 입자·배경 반동을 같은 프레임에 시작하며 60fps 기준 허용 오차는 1프레임(16.7ms)이다.

## 7. 구현 순서

1. 스킬 ID·직업·습득 구간·전용 시드 선택 및 기존 저장 마이그레이션
2. 600개 카탈로그와 무결성 검사
3. 1/2/3/4/5타 중앙 피해 숫자 시퀀스와 UI 전용 게이지 계단 감소
4. 20개 모션, 5개 리듬, 8개 궤적, 4개 카메라, 6개 마무리 프리셋
5. 물리·화염·냉기·번개·비전·암흑·맹독·바람·대지·신성·우주 VFX와 컬러 토큰
6. 12개 대표 스킬로 수직 슬라이스를 먼저 구현해 타격·숫자·게이지·잔상 제거를 에뮬레이터 검수
7. 전체 카탈로그 자동 매핑 후 63개 골든 캡처와 30초 반복 영상 검수
8. 미접속 동일성, RNG 불변, 장시간 안정성, Reduce Motion 회귀 검사

## 8. 완료 조건

- 직업별 카탈로그가 정확히 100개이고 ID·이름이 중복되지 않는다.
- 모든 스킬이 직접 피해 기술이며, 같은 습득 레벨의 총 배율이 같다.
- 레벨 5~100에서 정확히 20개를 중복 없이 습득한다.
- 기존 캐릭터의 레벨·능력치·장비·연대기·미접속 시간이 보존된다.
- 기본 공격은 이름 없이 중앙 피해 1회만 표시된다.
- 3연타 스킬은 3개의 피해 숫자와 3단계 게이지 감소가 같은 시점에 발생한다.
- 냉기 스킬은 전투 배경이 청색·서리 연출로 바뀌고 종료 후 완전히 복귀한다.
- 온라인과 오프라인 정산의 성장·장비·퀘스트 결과가 기존 계약과 동일하다.
- 애니메이션 종료 후 스킬명·피해 숫자·속성 오버레이가 남지 않는다.

### 자동 검증 게이트

- 직업 6개, 직업당 100개, 구간 1~20, 구간당 후보 5개가 정확하다.
- `catalogId`는 전역 중복이 없고 이름은 직업 안에서 중복이 없다.
- 모든 배율이 구간 공식과 일치하고 `hitWeights` 개수는 1~5, 합계는 100이다.
- 타격 시점 개수는 hitCount와 같고 오름차순이며 마지막 타격은 900ms 이전이다.
- 같은 시드의 신규 습득과 기존 저장 마이그레이션 결과가 매번 같다.
- `catalogId`, hitCount, element, 연출 프리셋을 바꿔도 동일 시간 정산 후 처치·레벨·퀘스트·아이템·장비·gameplay RNG 결과가 같다.
- 오프라인 정산 전후 presentation RNG가 변하지 않고 일시 연출 값이 남지 않는다.

### 연출팀 골든 캡처 63개

- 11개 속성 × 강도 저·중·고 3단계 = 33개
- 6직업 × 대표 연출 축 5개 = 30개
- 1·2·3·4·5타가 각각 최소 6회 이상 포함되어야 한다.
- 준비·첫 타격·마지막 타격·종료 후의 4프레임을 캡처한다.
- 1,200ms 프레임은 HUD를 제외하면 기본 전투 배경과 비교해 잔상 차이가 없어야 한다.
- 대표 12개는 Reduce Motion에서도 다시 캡처하며 카메라 이동 0, 숫자 겹침 없음, 마지막 게이지 목표 정확성을 확인한다.
